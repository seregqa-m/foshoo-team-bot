**Выбранный вариант, уточнение 15 октября:** временный **прерываемый** облачный сервер Selectel Standard. Пользователь принимает перерывы ради экономии и будет возобновлять сервер вручную с телефона; автоматическое восстановление VM пока не делаем. Бюджетные VDS распроданы. Приложение и порядок установки остаются прежними.

## 1. Что заказать

В панели «Продукты → Облачные серверы → Создать сервер»:

- Standard AMD, **2 vCPU / 4 ГБ RAM** — минимальная доступная пользователю конфигурация.
- В дополнительных настройках включить **«Прерываемый сервер»**. После создания и каждого восстановления он работает не более 24 часов и может остановиться раньше. Использовать сетевой загрузочный диск: данные локальных дисков при прерывании удаляются. [Условия Selectel](https://docs.selectel.ru/cloud-servers/about/preemptible-servers/).
- Ubuntu **24.04 x86_64**, вход по SSH-ключу.
- **Загрузочный SSD 10 ГБ**, тип «Универсальный v2», 2 000 IOPS из исходного расчёта. Это начальная оценка для текущей небольшой установки: frontend собирается на Mac, медиа остаются в Google Drive. После установки проверить свободное место через `df -h`; точный размер Linux-системы пока не измерен. 5 ГБ могут вместить минимальную систему, но оставляют мало места для обновлений. Прежние 25 ГБ были перенесены из фиксированного VDS-тарифа и не являются требованием приложения.
- В блоке «Интернет», поле «Подключение из интернета», выбрать **«Прямой публичный IP-адрес»**, создать один IPv4. По документации Selectel этот режим обеспечивает входящий и исходящий интернет без облачного роутера; отдельная приватная сеть для одного сервера приложения не требуется. «Публичный плавающий IP-адрес» требует роутера и сейчас не нужен. Если прямой IP недоступен в выбранном пуле, сначала проверить доступные сетевые варианты и их итоговую цену.
- Входящие TCP 22 (по возможности со своего IP), 80 и 443; API 8000 слушает только localhost. После создания проверить исходящий HTTPS к Telegram и Google.

[Инструкция Selectel по созданию облачного сервера](https://docs.selectel.ru/cloud-servers/create/create-server/). Итог **2 981,73 ₽/месяц** на скриншоте относился к обычному серверу с **5 ГБ** диска и роутером. Для прерываемого сервера с 10 ГБ и прямым IP цену сверить в панели; бюджет 250 ₽ к этому варианту не относится. Платная панель управления приложением не требуется.

Панель старого сервера доступна, **диск недоступен, бэкапов нет** (подтверждено 14 октября). Запускаем новую SQLite и восстанавливаем сохранённые в Google календарь, роли, финансовые данные и доступность. Настройки спектакль–чат, суперадминов и напоминаний восстанавливаем вручную. История голосований и связи со старыми опросами без актуальной БД не восстановятся автоматически. Локальную апрельскую базу не используем как актуальную. Перенос не ждёт восстановления старого диска.

### Уведомления и ручное возобновление

Selectel [заявляет уведомление при выключении](https://selectel.ru/blog/interruptible-servers/). Владелец аккаунта получает уведомления по всем категориям и продуктам; доступны почта и Telegram. Точная доставка события `EXPIRED` в Telegram отдельно не описана: проверить при первом системном прерывании. Сейчас Telegram-уведомления не подключены нами и не проверены.

1. В панели открыть меню уведомлений справа сверху → **«Смотреть все» → «Мои настройки уведомлений»**.
2. В блоке **«Каналы»**, строке **Telegram**, нажать **«Подключить»** и открыть предложенную ссылку или QR-код.
3. Отправить `/start` официальному боту, открытому из панели. Проверить категории «Услуги и сервисы» и «Алерты» для облачных серверов, а также настройки уведомлений внутри Telegram-бота. [Подключение Telegram](https://docs.selectel.ru/account/configure-telegram-bot/), [центр уведомлений](https://docs.selectel.ru/account/notifications/notification-center/).
4. После прерывания открыть панель в браузере телефона → **«Продукты → Облачные серверы» → меню нужного сервера → «Возобновить»**. Проверить переход в `ACTIVE` и открытие приложения. Отдельного SSH-подключения для возобновления VM не требуется. [Восстановление сервера](https://docs.selectel.ru/cloud-servers/manage/restore-preemptible-server/).

После установки и включения службы по инструкции ниже бот запускается при загрузке ОС. Это не автоматическое восстановление выключенной VM. При первом прерывании проверить получение уведомления, сохранность записанной БД и возврат бота в работу. Если уведомление об остановке не доставляется, следующий вариант — внешний мониторинг `/health` с уведомлением, без автоматического запуска VM.

## 2. Собрать и отправить

На Mac, из корня проекта (заменить домен и `SERVER_IP`):

```bash
npm --prefix frontend ci
bash scripts/package-selectel.sh app.example.ru
scp dist/foshoo-selectel.tar.gz root@SERVER_IP:/tmp/
```

Ниже команды первоначальной установки для root на **пустом новом** сервере. На уже установленном сервере повторно их не выполнять. Если образ выдал другого SSH-пользователя, подключиться им и выполнить `sudo -i`.

```bash
apt-get update
apt-get install -y ca-certificates curl nginx certbot python3-certbot-nginx sqlite3
useradd --system --create-home --home-dir /opt/foshoo --shell /usr/sbin/nologin foshoo
install -d -m 755 /opt/foshoo /var/www/foshoo
install -d -m 700 -o foshoo -g foshoo /var/lib/foshoo /etc/foshoo
tar -xzf /tmp/foshoo-selectel.tar.gz -C /opt/foshoo
cp -R /opt/foshoo/frontend/build/. /var/www/foshoo/
chmod -R a+rX /var/www/foshoo
chown -R foshoo:foshoo /opt/foshoo
install -d -m 755 /opt/foshoo-tools
curl --proto '=https' --tlsv1.2 -fsSL https://astral.sh/uv/install.sh -o /tmp/foshoo-uv-install.sh
UV_UNMANAGED_INSTALL=/opt/foshoo-tools sh /tmp/foshoo-uv-install.sh
cd /opt/foshoo
sudo -u foshoo env UV_PYTHON_INSTALL_DIR=/opt/foshoo/runtime /opt/foshoo-tools/uv --no-config python install 3.11.15
sudo -u foshoo env UV_PYTHON_INSTALL_DIR=/opt/foshoo/runtime /opt/foshoo-tools/uv --no-config venv --python 3.11.15 --managed-python --seed /opt/foshoo/.venv
sudo -u foshoo /opt/foshoo/.venv/bin/python -c 'import sys, pyexpat; assert sys.prefix != sys.base_prefix; print(sys.version, pyexpat.EXPAT_VERSION)'
sudo -u foshoo /opt/foshoo/.venv/bin/python -m pip install -r /opt/foshoo/backend/requirements.txt
sudo -u foshoo /opt/foshoo/.venv/bin/python -m pip check
install -m 600 /opt/foshoo/deploy/selectel.env.example /etc/foshoo.env
```

Для Ubuntu 26.04 используется отдельный [Python из uv](https://docs.astral.sh/uv/guides/install-python/), проверенной версии 3.11.15. Приложение и все последующие Python-команды запускаются через `/opt/foshoo/.venv/bin/python`; macOS `.venv` не переносится. Каталог `/opt/foshoo/runtime` нужен virtualenv и сохраняется при обновлении кода. `cd /opt/foshoo` и `--no-config` предотвращают попытку служебного пользователя читать `/root/uv.toml`.

## 3. Вернуть конфигурацию и данные

В `nano /etc/foshoo.env` заполнить токен того же бота, свой числовой `ADMIN_ID`, домен, ID календаря и Google-таблицы, прежний `GROUP_CHAT_ID` для действующей проверки доступа. При необходимости заполнить канал модерации, получателя отчётов, ID афиш. `YANDEX_*` не нужны.

Ключ Google передать отдельно с Mac:

```bash
scp backend/credentials.json root@SERVER_IP:/etc/foshoo/credentials.json
```

На сервере: `chown foshoo:foshoo /etc/foshoo/credentials.json` и `chmod 600 /etc/foshoo/credentials.json`. Проверить, что этому сервисному аккаунту доступны календарь, таблица и нужные файлы Drive. Сам доступ человека к Google-документу не заменяет права сервисного аккаунта.

**Импорт старой SQLite пропускаем:** приложение создаст новую БД в `/var/lib/foshoo/theater_bot.db`. Локальную апрельскую базу не загружаем. Ссылки ресурсов восстанавливаем из известных адресов. Если старая база станет доступна позже, сначала отдельно сверим её с новыми данными; не заменяем ею уже работающую БД.

## 4. Первый запуск и домен

Оставить `RECOVERY_MODE=true`, `POLL_AUTOMATION_ENABLED=false`, `LLM_ENABLED=false`, `ASSISTANT_ENABLED=false`.

```bash
install -m 644 /opt/foshoo/deploy/foshoo.service /etc/systemd/system/foshoo.service
systemctl daemon-reload
systemctl enable --now foshoo
curl --fail http://127.0.0.1:8000/health
```

Ожидается `status: recovery`. В этом режиме создаётся/мигрирует только локальная БД; Telegram, Google, модерация и API приложения ещё не работают. Если запуск неудачен: `journalctl -u foshoo -n 60 --no-pager` (секреты из env не публиковать).

В DNS домена поменять A на IP нового сервера; старую AAAA убрать, если IPv6 на новом сервере не настроен. Затем:

```bash
install -m 644 /opt/foshoo/deploy/nginx.conf /etc/nginx/sites-available/foshoo
nano /etc/nginx/sites-available/foshoo
ln -s /etc/nginx/sites-available/foshoo /etc/nginx/sites-enabled/foshoo
nginx -t
systemctl reload nginx
certbot --nginx -d app.example.ru
```

В nginx и certbot заменить `app.example.ru` тем же доменом, с которым собран frontend. Certbot запускать после обновления DNS. При сохранении домена менять ссылку Mini App не требуется; при новом домене обновить её в BotFather и `MINI_APP_URL`.

## 5. Включить бота

1. Через старую панель остановить старую VM. Если остановку нельзя подтвердить, перед запуском новой копии перевыпустить токен **того же бота** в BotFather; исключить и фоновые записи старой копии в Google. Токен вводится в серверный env, не в чат.
2. Поставить `RECOVERY_MODE=false`, оставить `POLL_AUTOMATION_ENABLED=false`, выполнить `systemctl restart foshoo`. Начнут работать бот, модерация и синхронизации Google (в том числе подготовка столбцов расписания). Открыть приложение из Telegram, проверить календарь, составы и финансы; в «Настройках» восстановить таблицу спектакль–чат, суперадминов и параметры напоминаний. Действующая авторизация пока использует старые правила с Google Sheets/группой.
3. Если база новая, старые опросы не подхватятся автоматически. Разобрать их до включения автоматизации; не угадывать связи по похожим названиям. Проверить один новый опрос вручную. В версии с регистрацией по голосам повторные экспорты доступности и добавление участников в Sheets работают независимо от автоматических публикаций, вне `RECOVERY_MODE`.
4. Модерация сохраняет автоудаление явного спама (`MODERATION_AUTO_DELETE=true`) и отчёты в личку. Для ручного подтверждения можно задать `false`. Проверяются сочетания признаков лёгкого заработка, казино и инвестиционного спама. Ссылки, критика и мат сами по себе разрешены. Регулярки не понимают цитаты и могут пропускать незнакомый спам; это более узкая проверка, чем LLM.
5. Когда связи и публикации сверены, поставить `POLL_AUTOMATION_ENABLED=true`, затем `systemctl restart foshoo`. Проверить `/health`, отсутствие polling conflict в журнале и реальную работу Mini App. LLM остаётся выключенной.

## 6. Копия вне сервера

До обновлений и регулярно делать согласованный снимок (на сервере):

```bash
install -d -m 700 -o foshoo -g foshoo /var/lib/foshoo/backups
sudo -u foshoo sqlite3 /var/lib/foshoo/theater_bot.db ".backup '/var/lib/foshoo/backups/latest.db'"
chmod 600 /var/lib/foshoo/backups/latest.db
```

С Mac скачать `scp root@SERVER_IP:/var/lib/foshoo/backups/latest.db ./foshoo-backup.db`. Локальная копия на той же VM не защищает от потери сервера. Следующий шаг эксплуатации — автоматические внешние бэкапы БД и защищённая копия конфигурации; в этих шаблонах они пока не настроены.

## Обновление бэкенда и фронтенда

На сервере установлена копия из архива, без `.git`: `git push` сам по себе
её не обновляет. Бэкенд работает через `foshoo.service`, фронтенд — статические
файлы nginx в `/var/www/foshoo`. Node на сервере не нужен.

После проверки и коммита изменений, **на Mac из корня проекта**:

```bash
bash scripts/package-selectel.sh app.foshoo-theatre.ru
scp -i ~/.ssh/id_ed25519_foshoo_selectel dist/foshoo-selectel.tar.gz deploy/update-selectel.sh root@87.228.36.209:/tmp/
ssh -i ~/.ssh/id_ed25519_foshoo_selectel root@87.228.36.209 'bash /tmp/update-selectel.sh /tmp/foshoo-selectel.tar.gz'
```

Сборщик отказывается работать при незакоммиченных изменениях, включая новые
неигнорируемые файлы. Исходники извлекаются через `git archive` из конкретного
коммита, frontend собирается из этой копии, SHA записывается в `REVISION`.
Изменение рабочей копии во время сборки также прерывает выпуск архива.
Локальные `output/`, `tmp/` и `knowledge-base/` игнорируются и в релиз не входят.
Скрипт установки определяет пользователя по `foshoo.service` (на Cloud.ru —
`foshoo-app`, на Selectel — `foshoo`). Скрипт установки:

- сохраняет код, фронтенд, env и согласованный снимок SQLite в закрытый
  каталог `/var/backups/foshoo/<дата>-<SHA>`;
- останавливает бота на время замены кода, сохраняет серверный virtualenv,
  `/etc/foshoo.env`, Google-ключ и базу в `/var/lib/foshoo`;
- публикует статику и перезапускает одну службу `foshoo`, проверяя `/health`;
- при ошибке возвращает старый код и статику. База автоматически не
  откатывается, чтобы не потерять ответы, принятые после запуска.

Этот скрипт рассчитан на совместимые, добавляющие данные миграции.
При изменении `requirements.txt` он остановится **до установки**: сначала
нужно отдельно подготовить и проверить серверный virtualenv. Для удаления
или переименования данных в БД нужен отдельный план миграции.
Шаблоны nginx и systemd автоматически не переустанавливаются.

Проверка после обновления:

```bash
cat /opt/foshoo/REVISION
systemctl is-active foshoo nginx
curl -fsS https://app.foshoo-theatre.ru/health
journalctl -u foshoo --since '5 minutes ago' --no-pager
```

После обновления закройте и заново откройте Mini App в Telegram, чтобы
загрузился новый фронтенд. Резервные копии хранятся на том же сервере;
внешнее автоматическое резервирование пока не настроено.
