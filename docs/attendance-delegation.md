# Ответы за участников

На вкладке «Мои даты» суперадминистратор видит выбор «Чьи даты».
По умолчанию открыты собственные ответы. Выбор имени открывает календарь этого
участника; заметная подпись указывает, за кого сейчас вносится ответ.
Доступны «Могу», «Не могу» и «Пока не знаю» на сегодня и будущие даты,
включая дни без опроса или предыдущего ответа. Можно выбрать любого известного
боту участника подключённых групп, включая себя и других суперадминистраторов.
Обычные участники и администраторы групп по-прежнему меняют только свои
существующие ответы. Прошедшие даты остаются доступны только для просмотра.

Список собирается из известных Telegram ID: входов в приложение, регистраций
голосовавших, событий членства и суперадминистраторов. Telegram-членство
проверяется при загрузке списка, открытии чужого календаря и каждой записи.
Полный состав группы Bot API не перечисляет. Если человека нет в списке,
ему достаточно открыть мини-приложение, после чего суперадминистратор обновляет
список. Имя берётся из связанной записи труппы либо из Telegram; username или ID
помогает различать тёзок. Имена из текстовых списков автоматически не сопоставляются.
Сбой проверки списка показывает предупреждение о неполноте; сбой проверки
конкретного участника запрещает чтение/запись до успешной повторной проверки.

## API и хранение

- `GET /api/attendance/participants` — имена и Telegram ID подтверждённых участников;
  только суперадминистратор, роль проверяется в БД.
- `GET /api/attendance/participants/{target_id}?month=YYYY-MM` — месячные ответы,
  локальная дата `today` и разрешение создавать первые ответы `can_create`.
- `PUT /api/attendance/participants/{target_id}` — `date`, `answer`,
  `expected_revision`. Нулевая ревизия означает отсутствие ответа на эту дату.
- `/api/attendance/me` сохраняет прежние ограничения и проверку собственной
  личности через подписанный initData. Общая защита полей `user_id`/`username`
  не ослабляется; целевой участник задаётся отдельным маршрутом.

Используется общий журнал `DayAnswer` с ключом `(Telegram ID, дата)` и
`answer_lock`. Источник `app-admin:<actor_id>:<date>:<expected_revision>`
фиксирует автора изменения в `AnswerHistory`; целевой ID записан в `user_id`.
Роль суперадминистратора и привязка группы повторно проверяются после ожидания
Telegram и перед записью. Повтор после потерянного ответа идемпотентен,
пока текущая запись совпадает с этим изменением. Более новый ответ из приложения
или опроса приводит к `409`; интерфейс перечитывает данные. Равнозначный ответ
не создаёт новую ревизию и не меняет источник.

Новый участник ставится в существующую очередь регистрации в Sheets по
проверенной Telegram-личности. Новые ответы поступают в обычный минутный экспорт;
сбой Sheets не отменяет сохранение. Роли в таблице и старые Telegram-отметки
не меняются. Никаких дополнительных постоянных прав доступа запись не выдаёт.
Миграция схемы не требуется. Эксплуатационная модель остаётся прежней:
один процесс backend с общим локальным lock.

Возможность добавлена в интерфейс «Мои даты». Новых инструментов ассистента
нет; автоматически переносить текстовые списки отсутствий ассистент не умеет.

## Проверка

`backend/tests/test_personal_attendance.py` проверяет права, других суперадминов,
первый ответ, повтор запроса, конфликт с новым голосом, отзыв роли, выход из группы
и отказ Telegram. Frontend-тесты проверяют выбор имени, пустую дату,
поздние ответы при переключении людей, блокировку переключения во время сохранения
и перечитывание при конфликте. Внешние Telegram/Sheets-вызовы в тестах подменены.
