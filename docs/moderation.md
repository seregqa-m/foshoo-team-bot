# Модерация публичных комментариев

Подтверждённый спам удаляется, его автор блокируется без срока в связанной
группе комментариев. При `MODERATION_AUTO_DELETE=true` уверенное решение
«спам» выполняется автоматически; сомнения и ошибки модели требуют кнопки
модератора. При `false` удаление и бан выполняются только после подтверждения.
Правило «автор не блокируется» больше не действует.

Бот должен быть администратором с `can_delete_messages` и
`can_restrict_members`. Если права на бан отсутствуют, удаление остаётся
доступно, а уведомление сообщает о неудавшейся блокировке.
Внутренние группы театра, собственный канал, анонимные администраторы и
проверенные администраторы группы исключены из этой модерации.

Для пользователей применяется `banChatMember`, для сообщений от имени
сторонних каналов — `banChatSenderChat` с сохранённым ID канала. ID никогда
не восстанавливается по имени или тексту. В старых записях без ID канала
возможна только ручная блокировка. Пересланный модератору текст не является
подтверждённым источником для удаления или бана.

Особенности [Telegram Bot API](https://core.telegram.org/bots/api#banchatmember):
бан пользователя в супергруппе также удаляет остальные его сообщения в ней;
это указано в карточке подтверждения. Бан канала запрещает его владельцу
писать в этой группе от имени своих каналов.

Перед баном повторно проверяются группа, права бота, статус администратора
у автора и отсутствие более нового изменения комментария. Удаление и бан
имеют независимые результаты. После подтверждённого удаления попытка бана
записывается в `moderation_bans` до вызова Telegram. Таймаут, потеря ответа
или остановка процесса требуют ручной проверки; автоматический повтор для
того же автора в той же группе запрещён, пока неопределённость не устранена.
Неуспешный бан не отменяет уже выполненное удаление и не отображается как
успешный. Дубликаты обработанных событий и кнопок не повторяют действия.

При обновлении `create_all` создаёт `moderation_bans`, миграция добавляет
nullable `moderation_comments.sender_chat_id`. Старый аудит сохраняется.
Массовая блокировка по историческим решениям не запускается. Уже удалённые
комментарии не переобрабатываются. Применяются только новые решения и
подтверждение ещё ожидающих проверки комментариев.
